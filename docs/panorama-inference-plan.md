## Baseline contract and preprocessing

- The [container entry point](https://github.com/DIAGNijmegen/PANORAMA_baseline/blob/main/src/process.py) reads one contrast-enhanced venous CT from `/input/images/venous-ct/*.mha` and `/input/clinical-information-pancreatic-ct.json` with `age`, `sex`, `study_date`, and `scanner`. It currently prints those fields. For any company or clinical case, confirm permission and prevent identifiable metadata entering logs. The current local MSD sample is NIfTI; a **derived** MHA would need an independently checked NIfTI-to-SimpleITK conversion preserving physical geometry. Keep the source untouched. CT phase and intensity calibration cannot be inferred from `.nii.gz` alone.
- [Inference code](https://github.com/DIAGNijmegen/PANORAMA_baseline/blob/main/src/process.py) resamples a working copy to `(4.5, 4.5, 9.0)` mm with the [custom B-spline resampler](https://github.com/DIAGNijmegen/PANORAMA_baseline/blob/main/src/data_utils.py). nnU-Net v2 applies its saved plan's own preprocessing/normalization. Do not substitute generic windowing for the saved plans. Confirm input orientation, origin, spacing and voxel intensity range before a pilot.
- Stage 1 uses `Dataset103_PANORAMA_baseline_Pancreas_Segmentation`, `nnUNetTrainer`, `3d_fullres`, `checkpoint_final.pth`, folds 0–4. It predicts a low-resolution binary pancreas mask. The [crop function](https://github.com/DIAGNijmegen/PANORAMA_baseline/blob/main/src/data_utils.py) transforms that mask's extent into original CT index space and expands by **100, 50, 15 mm** (code values; the README calls them cm, an apparent unit error). An empty pancreas mask currently fails an assertion/minimum operation; the pilot needs an explicit failure check.
- Stage 2 uses `Dataset104_PANORAMA_baseline_PDAC_Detection`, custom CE trainer, `3d_fullres`, `checkpoint_best_panorama.pth`, folds 0–4, on the crop. Its [label schema](https://github.com/DIAGNijmegen/PANORAMA_baseline/blob/main/src/nnUNet_results/Dataset104_PANORAMA_baseline_PDAC_Detection/nnUNetTrainer_Loss_CE_checkpoints__nnUNetPlans__3d_fullres/dataset.json) is tumor 1, veins 2, arteries 3, pancreas 4, pancreatic duct 5 and common bile duct 6. The code retains class-1 probability only inside a dilated predicted pancreas class (4 plus 5), extracts lesion candidates with `report_guided_annotation`, then pastes the crop into a full-size SimpleITK image and copies the source geometry. Validate that resulting physical space matches the input, including direction/origin and array axis order. Keep original NIfTI geometry and files intact.

## Actual outputs versus project goals

The shipped container writes `/output/images/pdac-detection-map/detection_map.mha` and `/output/pdac-likelihood.json`. The map is a full-size **detection map**, derived from candidate extraction, not a Grad-CAM/attention explanation. The JSON is the maximum candidate value called `patient_level_prediction` in code. It is an **uncalibrated model score**, not a clinical risk probability. Internal nnU-Net `.nii.gz` segmentations and `.npz` class probabilities are working files; pancreas segmentation, separate lesion masks, boxes, head/body/tail labels, diameter/volume, calibrated risk and explanatory heatmap are **not exposed as final container outputs**. Our problem statement requires these additional outputs or validated derivations. A threshold for a binary mask and candidate localization must be chosen and evaluated on independent data before claiming detection or segmentation. Do not relabel probabilities or the detection map as explanation.

## Dependencies, licenses and compute

- The [code repository](https://github.com/DIAGNijmegen/PANORAMA_baseline) is Apache-2.0. Its [Dockerfile](https://github.com/DIAGNijmegen/PANORAMA_baseline/blob/main/Dockerfile) starts from NVIDIA CUDA 12.2 runtime on Ubuntu 20.04, installs Python 3.9, an unpinned clone of nnU-Net and packages from [requirements.txt](https://github.com/DIAGNijmegen/PANORAMA_baseline/blob/main/requirements.txt), including SimpleITK, evalutils, NumPy, SciPy, scikit-image and report_guided_annotation. Pin and record an actual compatible image/dependency revision before the GPU pilot; the present Dockerfile does not fully lock dependencies. Its `test_run.sh` requests `--gpus all` and `--shm-size=16g`; **16 GiB shared-memory allocation is a script setting, not a measured RAM minimum**. GPU VRAM, peak host RAM, disk after extraction, and runtime per case are unknown until a pilot.
- The [Zenodo weight record](https://zenodo.org/records/11160381) lists 613,484,406-byte pancreas and 1,143,995,491-byte PDAC archives (1,757,479,897 bytes total, about 1.64 GiB compressed), plus a separate `LICENSE.txt` whose text is **CC BY-NC 4.0**. No archives were downloaded or installed. Clarify noncommercial permission for any company use. The [PANORAMA imaging/labels page](https://panorama.grand-challenge.org/datasets-imaging-labels/) and [dataset access notes](dataset-access.md) describe separate dataset access/licensing. Our local MSD sample is CC BY-SA 4.0. Do not assume code, weights and datasets share a license.
- The original 8 GB integrated-GPU laptop is for intake/reporting. It has no verified suitable NVIDIA/CUDA runtime. Use one authorized Colab or company NVIDIA GPU case, and check actual available VRAM/RAM/storage before retrieving weights. Plan scratch space for both archives, extracted models, converted input, nnU-Net intermediates and output; the exact minimum is unknown. Never install CUDA or the ensemble on this laptop for preparation.

## One-case GPU pilot and acceptance checks

1. Confirm weight/data license and permission, venous CT suitability, authorized GPU runtime and storage. Record host GPU, VRAM, RAM, disk and source/model hashes. Pin the container revision and dependencies.
2. Transfer one permitted de-identified CT (the local public sample only for software smoke testing after its overlap is checked). Convert a copy to MHA, record voxel-to-world transforms and compare dimensions, spacing, physical corner points and representative intensities before running. Provide only the metadata JSON fields expected by the baseline, with no real identifiers in logs.
3. Run the unmodified pretrained two-stage pipeline on one case. Record wall time, observed peak GPU/host memory, disk, success/failure, internal mask and final output paths. Inspect pancreas mask, crop bounds, probabilities and candidate map; handle empty/invalid crop explicitly if encountered. Compare output image size, spacing, origin and direction to input. Never overwrite the original CT.
4. Inspect resulting map on the original geometry alongside the existing dataset annotation, clearly distinguishing the two. Add candidate locations, sizes, segmentation and separate explanation work only after validating their derivation. A one-case visual inspection cannot establish accuracy, calibration, or clinical utility.

## Evaluation independence

The baseline [fold lists](https://github.com/DIAGNijmegen/PANORAMA_baseline/tree/main/src) cover its development cases. The [official PANORAMA dataset page](https://panorama.grand-challenge.org/datasets-imaging-labels/) states that its 2,238-case public development set includes **194 MSD Task07 cases and 80 NIH cases**. The current `pancreas_290` is explicitly an MSD **training** case; its exact overlap with those 194 cases has not been resolved. Do not call it independent or report performance from it. Obtain baseline training/development source IDs or a provider-confirmed overlap audit, compare patient and study IDs and duplicate-image fingerprints across institutions, and select a patient-level held-out set with permitted labels. Record annotation provenance; PANORAMA can include AI-derived masks. Only then predefine detection and segmentation metrics and thresholds.
